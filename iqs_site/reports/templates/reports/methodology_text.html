1Normalize the Text

Step 2a — Chunk Level

2aWord-Set Jaccard (used for chunk matching)

For comparing individual chunks (paragraphs) within a page pair, the system uses a fast word-set Jaccard similarity. Each text is treated as a set of unique words, and Jaccard measures the overlap between the two sets.

J(A,B) = |words_A ∩ words_B| / |words_A ∪ words_B|

Word-set Jaccard is fast and sufficient for short chunks. It treats word order as irrelevant — "the tractor pulls the load" and "the load pulls the tractor" score 100%. For longer texts and page-level comparison, the system switches to shingling (Step 2b below).
Step 2b — Page Level

2bk-Shingle Extraction (used for page matching)

For comparing entire pages, the system uses 5-word shingles (also called k-grams or n-grams). A shingle is a sequence of k = {{ shingle_k }} consecutive words. A sliding window steps through the text one word at a time, producing one shingle per position.

Unlike word-set Jaccard, shingles are order-sensitive — they capture phrase-level patterns. Two texts that use the same words in different orders will have low shingle Jaccard even if they share many vocabulary words.

shingles = [" ".join(words[i : i+{{ shingle_k }}])
          for i in range(len(words) − {{ shingle_k }} + 1)]

Step 4

4Shingle Jaccard Similarity

Jaccard similarity between the two shingle sets is computed the same way as the word-set version — intersection divided by union. Because shingles are order-sensitive phrases rather than individual words, this score is generally lower than the word-set Jaccard for the same pair of texts.

J(A,B) = |A ∩ B| |A ∪ B| = {{ sh_intersection }} {{ sh_union }}

Step 5

5MinHash — Scaling to Millions of Shingle Pairs

When comparing full pages across many reports, computing exact Jaccard for every pair of shingle sets is too expensive — a single page may produce thousands of shingles, and comparing every pair of pages across hundreds of reports results in millions of set intersection computations.

MinHash solves this by replacing each shingle set with a compact signature — a vector of {{ "128" }} integers, one per hash permutation. The expected fraction of matching positions in two signatures equals the Jaccard similarity of the original sets. This reduces the storage and comparison cost from O(shingles) to O(128) per page.

m = MinHash(num_perm=128)
for shingle in shingles:
    m.update(shingle.encode("utf-8"))

similarity = minhash_A.jaccard(minhash_B) # ≈ true Jaccard

Pages are recorded as a PageMatch when their MinHash Jaccard is ≥ 5%. Within each page pair, individual chunk pairs are then compared using the faster word-set Jaccard, and those above 30% become ChunkMatch records.

Pipeline Summary

1. Extract text from PDF, group into paragraph chunks. 2. Normalise: lowercase, strip punctuation, tokenise. 3. Build 5-word shingle set for each page. 4. Compute 128-permutation MinHash signature for each page. 5. Compare all page pairs with MinHash Jaccard; record pairs ≥ 5% as PageMatch. 6. Within each PageMatch, compare every chunk pair by word-set Jaccard; record pairs ≥ 30% as ChunkMatch.
