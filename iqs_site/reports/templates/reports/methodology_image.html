1Resize to 32 × 32

Both images are scaled down to a fixed 32×32 pixel thumbnail using Lanczos resampling. This discards high-frequency detail and makes the hash robust to resizing, aspect-ratio changes, and minor cropping.

Step 2

2Convert to Grayscale

Color information is discarded. Each RGB pixel becomes a single luminance value using the standard perceptual weighting:

Y = 0.299 R + 0.587 G + 0.114 B

Green is weighted most heavily because the human eye is most sensitive to green light. Grayscale conversion makes the hash insensitive to color shifts, CMYK-to-RGB conversion, and JPEG chroma compression artifacts.

Step 3

3Discrete Cosine Transform (DCT)

The DCT works like a Fourier transform — it decomposes a signal into a weighted sum of cosine waves at increasing spatial frequencies. To build intuition, the chart below takes a single horizontal row of pixels (row 16) from the 32×32 grayscale image and shows exactly which cosine components combine to recreate it. Each component is labelled k: k = 0 is the flat DC average (overall brightness), and higher k adds progressively finer detail. The first 8 components (k = 0–7) are the ones the hash retains.

Extending to two dimensions: the DCT is applied along every row, then along every column. The result is a 32×32 grid where the column index is the horizontal frequency k and the row index is the vertical frequency. Step 4

4Extract 8×8 Low-Frequency Block & Find Median

Only the top-left 8×8 = 64 coefficients are kept. The first coefficient at [0,0] represents the image's average brightness (the DC term) and is excluded from threshold computation to avoid sensitivity to overall exposure. The median of all 64 values is then found — values above it will become 1, values at or below will become 0.

Warm colours in the grid = large positive coefficients (strong low-frequency energy). Cool colours = negative coefficients. The median line separates 1-bits from 0-bits.

The three images show each level of compression: full grayscale (1,024 values) → 8×8 float DCT (64 floats, ∼6% of data) → binary hash (64 bits, one bit each). If two images produce the same binary pattern, their hashes match — regardless of all the detail that was lost along the way.
Step 5

5Build the 64-Bit Perceptual Hash

Each of the 64 DCT coefficients is compared to the median. 1 if above, 0 if below (or equal). This creates a compact 64-bit fingerprint that captures the image's structural pattern while being insensitive to brightness, contrast, and compression level. The 64 bits are encoded as a 16-character hexadecimal string for storage.

Step 6

6Hamming Distance — Comparing the Two Hashes

The Hamming distance is simply the count of bit positions where the two hashes differ. A distance of 0 means perceptually identical; higher values mean more visual difference. Pairs with distance ≤ 10 are recorded as matches (out of 64 total bits).
